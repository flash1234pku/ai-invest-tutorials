1. tradingview-mcp：用 Claude Code 编写、编译和回放测试 Pine Script

一句话总结：一个本地 MCP 桥接工具，让 Claude Code 通过 Chrome DevTools Protocol 操作你电脑上的 TradingView 桌面端，帮你写、编译、调试和回放测试 Pine Script，适合用 TradingView 做策略研究的人。

怎么用
  1. 准备：TradingView 桌面端（仓库说明实时数据需要付费订阅）、Node.js 18+、Claude Code
  2. 安装：git clone https://github.com/tradesdontlie/tradingview-mcp.git，进入目录后运行 npm install
  3. 用调试端口启动 TradingView：Mac 运行 ./scripts/launch_tv_debug_mac.sh，Windows 运行 scripts\launch_tv_debug.bat，Linux 运行 ./scripts/launch_tv_debug_linux.sh，或手动加参数 --remote-debugging-port=9222
  4. 在 ~/.claude/.mcp.json 或项目里的 .mcp.json 加入 mcpServers.tradingview，command 填 node，args 填该仓库的 src/server.js 路径；然后让 Claude 运行 tv_health_check 确认已连接
  5. 上手：先拿一个自己的脚本测试编译修错，再用回放核对成交，最后验证提醒触发在哪根 K 线；每个工具也可以用 tv 命令行调用（如 tv pine compile）

注意：非 TradingView 官方工具，用的是未公开的内部接口，TradingView 更新后可能失效（仓库建议固定桌面端版本）；它不会下真实订单；作者自己也提到要留意 TradingView 的使用条款。

  • 开源仓库 tradesdontlie/tradingview-mcp（MIT，帖称约 6.1k stars、2.8k forks），在你自己的电脑上驱动 TradingView 桌面端
  • 可切换品种周期、管理指标和提醒、写/编译 Pine Script 并读取报错、K 线回放模拟买卖、截图回传给模型
  • 作者建议先测三件事：编译修错是否偷偷改了逻辑、回放成交是否与自己的回测一致、提醒是否在正确的 K 线触发

2. Grok Bot 多代理闭环：研究 → 分析 → 回测 → 验证/否决

一句话总结：一种用多个 Grok Bot 代理搭“自我纠错”量化研究闭环的思路：不追求生成更多策略，而是让每个策略在动用资金前先过样本外、交易成本、数据泄漏、稳健性和市场状态依赖等检查。适合已经能写回测、想减少假 alpha 的人。

怎么用
  1. 分角色：至少设一个“找想法”、一个“做回测”、一个“专门找漏洞”的代理（Grok Bot 可以建多个 Bot 分工）
  2. 把计算交给 Python 脚本，不让模型自己“心算”收益
  3. 写死否决规则：样本外表现、手续费和滑点、数据泄漏、参数稳健性、不同市场状态下的表现，任何一项不过就丢弃
  4. 通过的策略生成报告，由人来批准；反馈再喂回下一轮研究
  5. 具体提示词和完整拆解原帖未说明（帖子指向的长文未收录）

注意：原帖举例说，即使年化 48.6%、夏普 2.31 的回测也可能是假 alpha；这是方法论，不是现成工具，用到的模型和数据可能产生费用，原帖未说明。

  • 一个代理找想法，一个代理测试，一个代理专门拆台；结果通过验证或被否决前，循环不停
  • 流程：Research → Analyze → Backtest → Verify → Report → Feedback → Repeat
  • Grok Bot 负责协调，Python 负责计算，硬规则淘汰不合格策略，人工批准通过的结果

3. Claude Code 一人量化台提示词

一句话总结：一段贴进 Claude Code 用的量化台提示词，核心价值是它的风控纪律：模拟盘先行、小仓位起步、想法要说清收益来源、定期演练紧急停止。适合想给自己的 AI 交易实验加护栏的人。

怎么用
  1. 完整提示词在原帖图片里，正文未给出原文；可以打开原帖查看
  2. 搭建时把这四条写成硬规则：模拟盘至少 30 天才能上实盘
  3. 实盘初期限制单笔仓位（原帖为 100 美元）
  4. 每个策略想法都必须写明对手方和收益来源，答不上来就放弃
  5. 做一个紧急停止开关并每周测试一次；下单只由代码执行，不让模型直接下单

注意：“Jev”是什么以及如何接入，原帖未说明；“可能让你变富”是作者的营销说法，不可当真。

  • 卖点：把笔记本变成“一人量化台”；Opus 5.5 做研究，Jev 给每个信号打分，只有代码能动钱
  • 四条纪律：先模拟盘 30 天；实盘第一天单笔仓位上限 100 美元；每个想法都要回答“对手方是谁、谁在付钱给你”；每周演练一次紧急停止开关

4. 样本外崩塌案例：样本内 0.86、样本外 0.17 → NO EDGE

一句话总结：一个防过拟合的真实教训：只在旧数据上有效的规则不是优势，只是“记忆”。适合所有做回测的人，用来理解为什么必须留出模型没见过的数据做检验。

怎么用
  1. 回测前先按时间切分数据，例如一段用于构建规则，之后的年份完全不看
  2. 规则只在样本内调参，定好后再跑样本外
  3. 给结果分级：样本外接近样本内算 PASS，明显下降算 FRAGILE（收紧或放弃），大幅崩塌算 NO EDGE（放弃）
  4. 设一个独立的风控环节，有权否决任何交易并限制单项仓位
  5. QuantGPT 和 JEV 的具体接入方法原帖未说明

注意：0.86 / 0.17 指的是什么指标，原帖未说明；这里只取它防过拟合的方法，帖中的分仓打分系统未经验证。

  • 一条规则在构建所用的年份得分 0.86，在从未见过的年份（2015 年后切分）只有 0.17，系统判定为“没有优势”并淘汰
  • 分级：PASS（通过）/ FRAGILE（脆弱，收紧或放弃）/ NO EDGE（直接放弃）
  • 分工：Grok Bot 出想法，QuantGPT（远程 MCP）计算，JEV 评判，代码下单；风控席位有一票否决权，单项上限 4%

5. 本地 Claude Code 连接 Grok Bot：cursor-grokbot-agents 扩展

一句话总结：Cursor BDK 的 cursor-grokbot-agents 扩展，让你本地运行的代理去问你账号里已有的 Grok Bot，并把回复带回当前对话。适合想让本地写代码的代理和云端常驻的 Grok Bot 分工合作的人（例如本地跑回测，Grok Bot 做研究汇总）。

怎么用
  1. 按官方文档用 BDK 新建本地代理，可以直接用模板：bdk init ./grokbot --template grokbot-agents
  2. 在 bot/extensions/grokbot.ts 中引入 @cursor/bdk/extensions/cursor-grokbot-agents，并在 agents 列表里写明允许联系的 Bot 名称和用途说明
  3. 登录凭据：运行 bdk login，或设置 CURSOR_API_KEY 等环境变量
  4. 挂载后会出现 grokbot__ask、grokbot__check、grokbot__interrupt、grokbot__list 四个工具；提问时要把背景、事实和想要的回答格式写全，因为 Grok Bot 看不到本地对话
  5. 回复较慢时用 check 再取结果，方向错了就用 interrupt 停止

注意：agents 列表里名字拼错可能会新建一个空的 Bot；check/interrupt 能读写 Bot 对话，共享代理时要控制谁能用；Claude Code、Codex 具体怎么接入此扩展，原帖和文档都未详细说明；费用原帖未说明。

  • 装上 cursor-grokbot-agents 扩展后，本地的 Claude Code、Codex 可以和 Grok Bot 互相发消息
  • 官方文档：cursor.com/docs/bdk/guides/grokbot-agents

6. HyperGrok：开源七代理 Hyperliquid 交易台架构

⚠️ 仅供参考，加密合约高风险

一句话总结：一个开源的多代理交易台架构，可在 Grok Bot 里运行，也能作为插件装进 Claude Code、Cursor。值得学的是它的分工和审批流程：默认只读，只有执行代理持有密钥，每笔单都要你亲自批准。适合研究多代理系统怎么设计权限和风控的人。

怎么用
  1. 最省事：在 Grok Bot 添加公开的 HyperGrok Desk Lead 模板（x.ai/bot/3Fjt0kR65RoGjj5JNZJWp），发送 “Start the desk.”；或把仓库 README 里的 bootstrap 提示词贴给一个 Bot
  2. 默认是研究模式，只读 Hyperliquid 公开 /info 接口，不需要钱包；可以先运行 python3 scripts/opening_bell.py --coin ETH 看行情快照，再用 scripts/desk_doctor.py 自检
  3. 回测前用 scripts/research_dataset.py 收集指定时间段的数据（可加 --with-funding），并用 --verify 校验
  4. 想练习时只接 testnet 的 API 钱包（模拟资金）；风控代理会生成交易单，你回复 approve 加单号才会发送
  5. 只想学架构的话，直接读仓库里的角色设定和 SKILL 文件即可

注意：加密永续合约有杠杆，可能快速亏光本金；接主网钱包等于让代理动真钱，强烈建议只停在只读和 testnet；本条不构成推荐。

  • 开源仓库 galleonlabs/hypergrok-trading-desk：7 个角色、17 个技能，覆盖研究、风控、执行与复盘
  • 角色：Desk Lead、市场分析、研究分析、策略、风控、执行交易员、交易复盘
  • 每笔交易固定流程：想法 → 证据 → 风控签字 → 你批准 → 发送一次 → 对账 → 复盘
